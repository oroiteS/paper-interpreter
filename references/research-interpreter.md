# 阶段三：Research 论文解读

本文件仅供 `paper-interpreter` 的 Research 解读阶段使用；本阶段 agent 是解读文档的写作者和负责人。接收阶段二的完整初筛报告及「阅读建议」原文，在 YAML frontmatter 后、其他正文之前新增 `## 阅读建议`，原样保留阶段二建议及其理由；不要擅自改写。以下解读要求照常执行，其余正文结构的相对顺序不变。

将原始研究论文转化为适合学习的深度解读。只处理报告原创研究、方法、实验或理论结果的 research paper；综述、Survey 和 Review 论文不属于本技能的适用范围。不要仅凭标题判断类型；类型不明时先检查摘要、正文及贡献。确认是综述时说明不适用，不套用本流程。

## 输出与关联技能

- 输出 `paper/markdown/{论文名}/解读.md`；图片、提取文本和其他副产物统一放在同目录 `append/`。不生成独立速读文档。
- 动笔前加载 `kimi-obsidian-markdown`，遵循其 Obsidian 语法；库内图片用 `![[append/文件名]]`，外部链接用普通 Markdown 链接。
- **所有自绘图形必须加载并遵守 `/nature-figure`**，包括知识地图、流程图和任何其他图表；按该技能的 backend 选择、导出和质量检查要求执行，不擅自更改用户的绘图偏好，也不使用 Mermaid 等其他方式绕过该技能。原论文图表的提取和引用不是自绘。
- 只在图形确实比文字更有助于理解时绘图；图片或依赖不可用时如实说明，不虚构图表或数据。

## 1. 获取并核对论文

读取用户提供的 PDF 或 URL，获取全文、图注、实验结果和必要的补充材料。使用适当的 PDF 工具提取文本与关键图表；必要时截取完整的矢量图或表格页面区域并核对清晰度，不依赖仅提取嵌入式位图。记录标题、作者、年份、发表渠道和原文链接；未能确认的项目标为未知。

优先保留与解读直接相关的原论文架构图、流程图、关键实验图及复杂结果表格，保存到 `append/` 并标明原图表编号。原论文有合适图表时直接引用并解释，不机械重绘；若没有合适原图，先用文字说明，仅在确有必要时依照 `/nature-figure` 绘制示意图，并注明是示意图。不得补造原文没有的机制或数值。

## 2. 撰写解读

以下四部分均须覆盖，篇幅随论文复杂度调整。关键事实、公式、数字和图表引用应能追溯到原文章节、图表或页码；区分作者的结论和自己的推断，证据不足时明确说明。

### 📍 论文定位

用一句话概括研究问题、方法和主要结论；说明研究价值和潜在应用，适合时用简短类比建立直觉。不要把未经证实的潜力写成已实现的效果。

### 🗺️ 知识地图

**默认用文字**，按理解本文的必要性组织为核心、支撑和可选扩展知识；解释核心概念是什么、为什么与本文有关，必要时用类比和难度标记辅助。关系复杂、文字难以讲清时才绘图，且必须使用 `/nature-figure`；保存图片及其 QA 副产物到 `append/`，标注为示意图。不要为了满足格式而画图。

### 🔬 论文精读

围绕问题、方案和验证展开：

- **Why**：研究动机、已有方法的不足和研究问题。
- **What**：提出的方法或系统，结合原文关键架构图解释。
- **How**：关键机制、设计选择、必要公式或算法；公式配白话解释。
- **So What**：实验任务、数据、基线、指标和核心结果，说明比较条件；大表优先引用原图并用文字提炼，避免抄写庞大数据表。
- **Now What**：研究价值及可能应用，区分论文证据与合理推测。

### ⚖️ 批判性评估

结合原文证据讨论假设是否合理、实验与基线是否充分、方法适用边界和局限、未来改进方向。区分论文承认的限制与解读者的判断；不凭空断言缺失或缺陷。

### 文档头部字段

解读文档最前面必须填写以下 YAML frontmatter，保留全部字段及顺序：

```yaml
---
title:
abbreviation:
author:
type: Research
venue:
year:
url:
status: reading
tags: []
paper_date:
benchmark: []
code_repository:
---
```

根据论文或可信的官方来源填写标题、论文常用缩写、作者、发表渠道、年份、原文链接、论文发表或提交日期、使用的 benchmark 和官方代码仓库链接；`benchmark` 使用 YAML 列表。`type` 固定为 `Research`，`status` 默认为 `reading`，`tags` 按需填写且默认使用英文标签。未知或无法核实的标量字段留空、列表字段留 `[]`，不编造缩写、日期或代码链接；日期明确时使用 `YYYY-MM-DD`。需要时对字符串加引号，保证 YAML 有效。

不要设置术语词典或参考资料独立章节，必要术语在首次出现处解释。

## 3. 写入、强制审阅与修订

阶段三 agent 亲自将完整解读写入 `paper/markdown/{论文名}/解读.md`；覆盖已有文件前先读取并保留用户内容。

写入后**无需询问用户，必须派遣一个只读审阅 subagent**，提供原论文 PDF 路径或 URL、解读文档路径和用户已有的审阅侧重点，让其自行对照原文核查事实、数字、图表、完整性及逻辑，返回「位置 + 问题或原文 + 建议」和审阅结论。若无法派遣或审阅失败，不得声称已审阅；报告阻碍，待可用时完成审阅。

**写保护**：阶段三 agent 派遣的所有审阅 subagent 只读，绝不修改、覆盖、删除 `解读.md` 或另存替代稿。派发后阶段三 agent 必须暂停对解读文档的一切读写和改动，等待返回；同一时刻只允许一个与解读文档相关的 subagent 运行。审阅返回后由阶段三 agent 核对建议，亲自修正有依据的问题，保留并说明无法确认的问题。

## 4. 固定收尾与交付

审阅修订完成后，阶段三 agent 在学习库根目录（`scripts/` 和 `paper/` 所在目录）执行：

```bash
python3 scripts/math.py "paper/markdown/${PAPER_NAME}/解读.md"
```

该脚本负责公式定界符及标点后处理。执行前确认脚本存在；脚本缺失或非零退出时停止并报告，不静默跳过或自行代写。运行成功后检查文档、引用图片和关键公式是否正常。

最终汇报解读文件路径、审阅结论及主要修订、公式后处理结果；对未能核实的内容或未完成的步骤明确说明。

## 质量检查

- [ ] 文档开头包含完整指定字段的 YAML frontmatter，已核实的内容正确填写，未知内容留空。
- [ ] 论文属于原始研究，结论和关键数字可追溯原文。
- [ ] 四个板块完整，知识地图默认文字，仅在复杂且必要时绘图。
- [ ] 自绘图均遵守 `/nature-figure`；合适的原图优先直接引用。
- [ ] 未生成独立速读文档，也未设置术语词典或参考资料章节。
- [ ] 已不经询问派出只读审阅 subagent，等待其返回并由阶段三 agent 修订。
- [ ] 所有副产物位于 `append/`，Obsidian 图片引用有效。
- [ ] 已运行 `scripts/math.py`；失败时已明确报告。
