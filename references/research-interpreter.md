# 阶段三：Research 论文解读

本文件仅供 `paper-interpreter` 的 Research 解读阶段使用；本阶段 agent 是解读文档的写作者和负责人。接收阶段二的完整初筛报告及「阅读建议」原文，在 YAML frontmatter 后、其他正文之前新增 `## 阅读建议`，原样保留阶段二建议及其理由；不要擅自改写。以下解读要求照常执行，其余正文结构的相对顺序不变。

将原始研究论文转化为适合学习的深度解读。只处理报告原创研究、方法、实验或理论结果的 research paper；综述、Survey 和 Review 论文不属于本技能的适用范围。不要仅凭标题判断类型；类型不明时先检查摘要、正文及贡献。确认是综述时说明不适用，不套用本流程。

## 写作与关联技能

- 不生成独立速读文档。
- 动笔前加载 `kimi-obsidian-markdown`，遵循其 Obsidian 语法；图片使用有效的 Obsidian 引用，外部链接用普通 Markdown 链接。
- **所有自绘图形必须加载并遵守 `/nature-figure`**，包括知识地图、流程图和任何其他图表；按该技能的 backend 选择、导出和质量检查要求执行，不擅自更改用户的绘图偏好，也不使用 Mermaid 等其他方式绕过该技能。原论文图表的提取和引用不是自绘。
- 只在图形确实比文字更有助于理解时绘图；图片或依赖不可用时如实说明，不虚构图表或数据。

## 1. 获取并核对论文

读取用户提供的 PDF 或 URL，获取全文、图注、实验结果和必要的补充材料。记录标题、作者、年份、发表渠道和原文链接；未能确认的项目标为未知。

### 原论文图表截取硬性规范（必须遵守）

- **严禁用 Markdown 改写原论文已有的图或表**：凡论文中已有的 Figure 和 Table（无论主文还是附录、无论表格大小、无论完整呈现还是部分摘录），**一律禁止**使用 Markdown 表格抄写、转写、改写或节选重排，也禁止用 Mermaid / ASCII 重绘。需要展示原文图或表时，**必须使用从原论文精确裁剪的截图**，标明原图表编号，并在截图下方用文字要点提炼核心发现与关键数值。仅当原论文**本身不存在对应表格**、为跨段落归纳概念对照确有必要时，才可自行编写简短的 Markdown 表格（并保证语法规范、表头与数据行间无空行），不得借“精简对比”之名改写原文已有 Table。
- **严禁嵌入整页 PDF 截图，必须精准裁剪**：不得依赖仅提取嵌入式位图（矢量图和 LaTeX 表格会缺失或残缺），更**严禁将整页 PDF 渲染图直接嵌入文档**。对每一张需要引用的原论文 Figure 或 Table，必须以高分辨率（建议 200–300 DPI）渲染目标页后，**紧密裁剪（crop）至单个目标图/表本体及其标题（caption）的紧凑外框**（保留完整坐标轴、图例、表头、表注和 caption，边缘仅留少量白边），不得混入周围大段正文、页眉页脚、页码或其他无关图表；双栏排版的单栏图表必须只裁出目标栏内对应区域。若阶段一未提供合规裁剪图（或仅提供整页图/零碎位图），本阶段必须直接从原 PDF 重新高清渲染并精准裁剪，保存至 `append/`（清晰命名如 `fig2_workflow.png`、`table1_main_results.png`）；整页中间图不得被 `解读.md` 引用。
- **强制逐张视觉核验**：每一张待嵌入的裁剪图在写入 `解读.md` 前，**必须实际打开查看图片内容**，核对四项：① 画面仅包含单个目标图/表本体及 caption，无整页或大段无关正文残留；② 上下左右边缘无裁断；③ 文字、公式与数字清晰可读；④ 编号与正文引用一致。任一项不达标必须调整裁剪框重新裁剪并再次查看，直至合格。
- **原图与自绘图边界**：原论文有合适图表时直接引用上述精准裁剪的原图并解释，不机械重绘；若没有合适原图，先用文字说明，仅在确有必要时依照 `/nature-figure` 绘制示意图，并注明是示意图。不得补造原文没有的机制或数值。

## 2. 撰写解读

以下四部分均须覆盖，篇幅随论文复杂度调整。关键事实、公式、数字和图表引用应能追溯到原文章节、图表或页码；区分作者的结论和自己的推断，证据不足时明确说明。

### 📍 论文定位

用一句话概括研究问题、方法和主要结论；说明研究价值和潜在应用，适合时用简短类比建立直觉。不要把未经证实的潜力写成已实现的效果。

### 🗺️ 知识地图

**默认用文字**，按理解本文的必要性组织为核心、支撑和可选扩展知识；解释核心概念是什么、为什么与本文有关，必要时用类比和难度标记辅助。关系复杂、文字难以讲清时才绘图，且必须使用 `/nature-figure`；自绘图标注为示意图。不要为了满足格式而画图。

### 🔬 论文精读

围绕问题、方案和验证展开：

- **Why**：研究动机、已有方法的不足和研究问题。
- **What**：提出的方法或系统，结合原文关键架构图解释。
- **How**：关键机制、设计选择、必要公式或算法；公式配白话解释。
- **So What**：实验任务、数据、基线、指标和核心结果，说明比较条件；凡原文已有实验结果表、消融表、对比表等 Table，**一律插入精准裁剪的原表截图**并在图下方用文字要点提炼核心发现与关键数值，**严禁用 Markdown 表格抄写、转写或节选重排原文已有表格**。
- **Now What**：研究价值及可能应用，区分论文证据与合理推测。

### ⚖️ 批判性评估

结合原文证据讨论假设是否合理、实验与基线是否充分、方法适用边界和局限、未来改进方向。区分论文承认的限制与解读者的判断；不凭空断言缺失或缺陷。

### 文档头部字段

解读文档最前面必须填写以下 YAML frontmatter，保留全部字段及顺序：

```yaml
---
title:
abbreviation:
author:
type: Research
venue:
year:
url:
status: reading
tags: []
paper_date:
benchmark: []
code_repository:
---
```

根据论文或可信的官方来源填写标题、论文常用缩写、作者、发表渠道、年份、原文链接、论文发表或提交日期、使用的 benchmark 和官方代码仓库链接；`benchmark` 使用 YAML 列表。`type` 固定为 `Research`，`status` 默认为 `reading`，`tags` 按需填写且默认使用英文标签。未知或无法核实的标量字段留空、列表字段留 `[]`，不编造缩写、日期或代码链接；日期明确时使用 `YYYY-MM-DD`。需要时对字符串加引号，保证 YAML 有效。

不要设置术语词典或参考资料独立章节，必要术语在首次出现处解释。

## 质量检查

- [ ] 文档开头包含完整指定字段的 YAML frontmatter，已核实的内容正确填写，未知内容留空。
- [ ] 论文属于原始研究，结论和关键数字可追溯原文。
- [ ] 四个板块完整，知识地图默认文字，仅在复杂且必要时绘图。
- [ ] 自绘图均遵守 `/nature-figure`；合适的原图优先直接引用。
- [ ] 未生成独立速读文档，也未设置术语词典或参考资料章节。
- [ ] 论文图片和图表的引用有效，且原图与自绘示意图的来源清楚。
- [ ] 未用 Markdown 表格抄写、转写、改写或节选重排任何原论文已有 Table（若存在自建 Markdown 表格，确认原文无对应表且语法渲染正常）。
- [ ] 所有嵌入的原论文图/表截图均已逐张打开查看复核：仅包含单个目标图/表本体及 caption，无整页 PDF 截图、无无关正文残留、无边缘截断且清晰可读。
