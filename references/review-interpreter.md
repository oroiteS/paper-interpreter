# 阶段三：Review 论文解读

本文件仅供 `paper-interpreter` 的 Review 解读阶段使用；本阶段 agent 是解读文档的写作者和负责人。接收阶段二的完整初筛报告及「阅读建议」原文，在 YAML frontmatter 后、其他正文之前新增 `## 阅读建议`，原样保留阶段二建议及其理由；不要擅自改写。以下解读要求照常执行，其余正文结构的相对顺序不变。

将综述论文转化为理解一个领域的知识文档，重点解释领域范围、作者的分类体系、技术路线、发展脉络和开放问题。适用于 Review、Survey 等综述，不适用于报告原创研究结果的原始研究论文。不要只凭标题判断类型；类型不明时检查摘要、正文与贡献。确认不是综述时说明不适用，不套用本流程。

## 输出与关联技能

- 输出 `paper/markdown/{论文名}/解读.md`；图片、提取文本和其他副产物统一放在同目录 `append/`。不生成独立速读文档。
- 动笔前加载 `kimi-obsidian-markdown`，遵循其 Obsidian 语法；库内图片用 `![[append/文件名]]`，外部链接用普通 Markdown 链接。
- **所有自绘图形必须加载并遵守 `/nature-figure`**，包括知识地图、分类树、时间线及其他图表；按该技能的 backend 选择、导出和质量检查要求执行，不擅自更改用户的绘图偏好，也不使用 Mermaid 等其他方式绕过该技能。原论文图表的提取和引用不是自绘。
- 默认以文字呈现，仅在确实有助理解时绘图。有合适原图时优先提取并解释，不机械重画。图片或依赖不可用时如实说明，不虚构图表或数据。

## 1. 获取并核对论文

读取用户提供的 PDF 或 URL，获取全文、图注和必要的补充材料。使用适当的 PDF 工具提取文本与关键图表；必要时截取完整的矢量图或表格页面区域并核对清晰度。记录论文信息、研究范围、作者的分类依据、代表性工作和文献检索截止日期；未报告或无法核实的内容明确标注，不以发表日期替代检索截止日期。

优先提取与解读直接相关的原文分类图、发展脉络图和关键比较表，保存到 `append/` 并标明原图表编号。没有合适原图时先用文字说明，确有必要才依照 `/nature-figure` 自绘并注明示意图，不补造原文没有的关系或数据。

## 2. 撰写解读

### 文档头部字段

解读文档最前面必须填写以下 YAML frontmatter，保留全部字段及顺序：

```yaml
---
author:
type: Review
venue:
url:
status: reading
tags: []
start_date:
finish_date:
paper_date:
---
```

只使用上述字段，不添加其他 frontmatter 字段。根据论文或可信官方来源填写作者、发表渠道、原文链接和论文发表或提交日期；`type` 固定为 `Review`，`status` 默认为 `reading`，`tags` 按需填写且默认使用英文标签。`start_date` 填实际开始阅读的系统日期，`finish_date` 尚未确定时留空；日期使用 `YYYY-MM-DD`。未知或无法核实的字段留空，不编造信息；需要时对字符串加引号，保证 YAML 有效。模板中的 Templater 代码仅供理解字段和格式，生成文档时不要写入或执行该代码。

### 正文模板

按以下标题顺序和 Obsidian callout 格式撰写，简明解读，不复制提示文字；正文主体可在对应 callout 之后展开。论文未涉及的部分注明未报告或不适用，不虚构内容。

```markdown
## Scope
> [!note] 综述范围
> 研究领域、覆盖范围、文献时间跨度、主要关注点与核心贡献。

## Problem & Preliminaries
> [!abstract] 问题与前置知识
> 问题定义、研究动机、必要的概念、符号及输入输出。

## Taxonomy
> [!note] 顶层分类体系
> 作者如何组织、划分现有工作及其依据。

## Framework & Key Methods
> [!summary] 核心技术路线
> 按分类体系解释主要机制、代表工作和关键比较。

## Baseline & Benchmark
> [!tip] 基线与基准
> 综述整理的基线、数据集、基准和评价指标，说明比较条件。

## Trends
> [!note] 范式演进与趋势
> 根据原文概括技术演进与关键取舍。

## Gap
> [!note] 局限与开放挑战
> 领域的未解问题、未来研究空白及综述本身的局限。

## 值得精读的论文
> [!tip] 论文
> - [[论文短名]] — 一句话入选理由
```

`Problem & Preliminaries` 中以前置知识文字说明代替强制独立知识地图；`Taxonomy` 默认用分层文字，必要时才绘图。`值得精读的论文` 从综述引用的工作中按需选择，不规定数量，无法确认时说明；它是阅读建议，不是参考资料目录。分类图、对比表和时间线均非必需，有合适原图优先引用，缺少依据不强行编造时间线或跨条件比较。

关键事实、数字、代表性论文和图表应能追溯到原文章节、图表或页码；区分综述作者观点、被综述工作的结论及解读者判断，区分发表时间与文献检索截止时间。必要术语在首次出现处解释，不设置独立术语词典或参考资料章节。不强制联网补充最新文献；用户另有要求时再扩展检索，并区分原文与新增资料。

## 3. 写入、强制审阅与修订

阶段三 agent 亲自将完整解读写入 `paper/markdown/{论文名}/解读.md`；覆盖已有文件前先读取并保留用户内容。

写入后**无需询问用户，必须派遣一个只读审阅 subagent**，提供原论文 PDF 路径或 URL、解读文档路径及用户已有的审阅侧重点，让其自行对照原文核查事实、数字、图表、完整性及逻辑，返回「位置 + 问题或原文 + 建议」和审阅结论。特别检查分类依据与代表性工作是否准确、是否混淆观点来源、是否把截止日期之前的结论当作当前最新，以及不同任务和指标下的结果是否被错误比较。若无法派遣或审阅失败，不得声称已审阅；报告阻碍，待可用时完成审阅。

**写保护**：阶段三 agent 派遣的所有审阅 subagent 只读，绝不修改、覆盖、删除 `解读.md` 或另存替代稿。派发后阶段三 agent 必须暂停对解读文档的一切读写和改动，等待返回；同一时刻只允许一个与解读文档相关的 subagent 运行。审阅返回后由阶段三 agent 核对建议，亲自修正有依据的问题，保留并说明无法确认的问题。

## 4. 固定收尾与交付

审阅修订完成后，阶段三 agent 在学习库根目录（`scripts/` 和 `paper/` 所在目录）执行：

```bash
python3 scripts/math.py "paper/markdown/${PAPER_NAME}/解读.md"
```

该脚本负责公式定界符及标点后处理。执行前确认脚本存在；脚本缺失或非零退出时停止并报告，不静默跳过或自行代写。运行成功后检查文档、引用图片和关键公式是否正常。

最终汇报解读文件路径、审阅结论及主要修订、公式后处理结果；对未能核实的内容或未完成的步骤明确说明。

## 质量检查

- [ ] 论文属于综述，frontmatter 字段完整，未知内容留空，标签默认英文。
- [ ] 原文分类、观点来源与文献时间范围准确，未把旧结论当作最新现状。
- [ ] 正文使用指定标题与 callout；前置知识和分类默认文字，自绘图遵守 `/nature-figure`，合适的原图优先直接引用。
- [ ] 未生成独立速读文档，也未设置术语词典或参考资料章节。
- [ ] 已不经询问派出只读审阅 subagent，等待其返回并由阶段三 agent 修订。
- [ ] 所有副产物位于 `append/`，Obsidian 图片引用有效。
- [ ] 已运行 `scripts/math.py`；失败时已明确报告。
