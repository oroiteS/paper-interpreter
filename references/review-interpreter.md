# 阶段三：Review 论文解读

本文件仅供 `paper-interpreter` 的 Review 解读阶段使用；本阶段 agent 是解读文档的写作者和负责人。接收阶段二的完整初筛报告及「阅读建议」原文，在 YAML frontmatter 后、其他正文之前新增 `## 阅读建议`，原样保留阶段二建议及其理由；不要擅自改写。以下解读要求照常执行，其余正文结构的相对顺序不变。

将综述论文转化为理解一个领域的知识文档，重点解释领域范围、作者的分类体系、技术路线、发展脉络和开放问题。适用于 Review、Survey 等综述，不适用于报告原创研究结果的原始研究论文。不要只凭标题判断类型；类型不明时检查摘要、正文与贡献。确认不是综述时说明不适用，不套用本流程。

## 写作与关联技能

- 不生成独立速读文档。
- 动笔前加载 `kimi-obsidian-markdown`，遵循其 Obsidian 语法；图片使用有效的 Obsidian 引用，外部链接用普通 Markdown 链接。
- **所有自绘图形必须加载并遵守 `/nature-figure`**，包括知识地图、分类树、时间线及其他图表；按该技能的 backend 选择、导出和质量检查要求执行，不擅自更改用户的绘图偏好，也不使用 Mermaid 等其他方式绕过该技能。原论文图表的提取和引用不是自绘。
- 默认以文字呈现，仅在确实有助理解时绘图。有合适原图时优先提取并解释，不机械重画。图片或依赖不可用时如实说明，不虚构图表或数据。

## 1. 获取并核对论文

读取用户提供的 PDF 或 URL，获取全文、图注和必要的补充材料。记录论文信息、研究范围、作者的分类依据、代表性工作和文献检索截止日期；未报告或无法核实的内容明确标注，不以发表日期替代检索截止日期。

### 原论文图表截取硬性规范（必须遵守）

- **严禁用 Markdown 改写原论文已有的图或表**：凡综述中已有的 Figure 和 Table（无论主文还是附录、无论表格大小、无论完整呈现还是部分摘录），**一律禁止**使用 Markdown 表格抄写、转写、改写或节选重排，也禁止用 Mermaid / ASCII 重绘。需要展示原文分类图、发展脉络图或比较表时，**必须使用从原论文精确裁剪的截图**，标明原图表编号，并在截图下方用文字要点提炼关键信息。仅当原论文**本身不存在对应表格**、为跨章节归纳概念对照确有必要时，才可自行编写简短的 Markdown 表格（并保证语法规范、表头与数据行间无空行），不得借“精简对比”之名改写原文已有 Table。
- **严禁嵌入整页 PDF 截图，必须精准裁剪**：不得依赖仅提取嵌入式位图（矢量图和 LaTeX 表格会缺失或残缺），更**严禁将整页 PDF 渲染图直接嵌入文档**。对每一张需要引用的原论文 Figure 或 Table，必须以高分辨率（建议 200–300 DPI）渲染目标页后，**紧密裁剪（crop）至单个目标图/表本体及其标题（caption）的紧凑外框**（保留完整坐标轴、图例、表头、表注和 caption，边缘仅留少量白边），不得混入周围大段正文、页眉页脚、页码或其他无关图表；双栏排版的单栏图表必须只裁出目标栏内对应区域。若阶段一未提供合规裁剪图（或仅提供整页图/零碎位图），本阶段必须直接从原 PDF 重新高清渲染并精准裁剪，保存至 `append/`（清晰命名如 `fig1_taxonomy.png`、`table2_comparison.png`）；整页中间图不得被 `解读.md` 引用。
- **强制逐张视觉核验**：每一张待嵌入的裁剪图在写入 `解读.md` 前，**必须实际打开查看图片内容**，核对四项：① 画面仅包含单个目标图/表本体及 caption，无整页或大段无关正文残留；② 上下左右边缘无裁断；③ 文字与数字清晰可读；④ 编号与正文引用一致。任一项不达标必须调整裁剪框重新裁剪并再次查看，直至合格。
- **原图与自绘图边界**：没有合适原图时先用文字说明，确有必要才依照 `/nature-figure` 自绘并注明示意图，不补造原文没有的关系或数据。

## 2. 撰写解读

### 文档头部字段

解读文档最前面必须填写以下 YAML frontmatter，保留全部字段及顺序：

```yaml
---
author:
type: Review
venue:
url:
status: reading
tags: []
start_date:
finish_date:
paper_date:
---
```

只使用上述字段，不添加其他 frontmatter 字段。根据论文或可信官方来源填写作者、发表渠道、原文链接和论文发表或提交日期；`type` 固定为 `Review`，`status` 默认为 `reading`，`tags` 按需填写且默认使用英文标签。`start_date` 填实际开始阅读的系统日期，`finish_date` 尚未确定时留空；日期使用 `YYYY-MM-DD`。未知或无法核实的字段留空，不编造信息；需要时对字符串加引号，保证 YAML 有效。模板中的 Templater 代码仅供理解字段和格式，生成文档时不要写入或执行该代码。

### 正文模板

按以下标题顺序和 Obsidian callout 格式撰写，简明解读，不复制提示文字；正文主体可在对应 callout 之后展开。论文未涉及的部分注明未报告或不适用，不虚构内容。

```markdown
## Scope
> [!note] 综述范围
> 研究领域、覆盖范围、文献时间跨度、主要关注点与核心贡献。

## Problem & Preliminaries
> [!abstract] 问题与前置知识
> 问题定义、研究动机、必要的概念、符号及输入输出。

## Taxonomy
> [!note] 顶层分类体系
> 作者如何组织、划分现有工作及其依据。

## Framework & Key Methods
> [!summary] 核心技术路线
> 按分类体系解释主要机制、代表工作和关键比较。

## Baseline & Benchmark
> [!tip] 基线与基准
> 综述整理的基线、数据集、基准和评价指标，说明比较条件。

## Trends
> [!note] 范式演进与趋势
> 根据原文概括技术演进与关键取舍。

## Gap
> [!note] 局限与开放挑战
> 领域的未解问题、未来研究空白及综述本身的局限。

## 值得精读的论文
> [!tip] 论文
> - [[论文短名]] — 一句话入选理由
```

`Problem & Preliminaries` 中以前置知识文字说明代替强制独立知识地图；`Taxonomy` 默认用分层文字，必要时才绘图。`值得精读的论文` 从综述引用的工作中按需选择，不规定数量，无法确认时说明；它是阅读建议，不是参考资料目录。分类图、对比表和时间线均非必需；若原文已有对应图或表且需要展示，必须插入精准裁剪的原图/原表截图并配文字提炼，严禁用 Markdown 表格改写原文已有 Table，缺少依据不强行编造时间线或跨条件比较。

关键事实、数字、代表性论文和图表应能追溯到原文章节、图表或页码；区分综述作者观点、被综述工作的结论及解读者判断，区分发表时间与文献检索截止时间。必要术语在首次出现处解释，不设置独立术语词典或参考资料章节。不强制联网补充最新文献；用户另有要求时再扩展检索，并区分原文与新增资料。

## 质量检查

- [ ] 论文属于综述，frontmatter 字段完整，未知内容留空，标签默认英文。
- [ ] 原文分类、观点来源与文献时间范围准确，未把旧结论当作最新现状。
- [ ] 正文使用指定标题与 callout；前置知识和分类默认文字，自绘图遵守 `/nature-figure`，合适的原图优先直接引用。
- [ ] 未生成独立速读文档，也未设置术语词典或参考资料章节。
- [ ] 论文图片和图表的引用有效，且原图与自绘示意图的来源清楚。
- [ ] 未用 Markdown 表格抄写、转写、改写或节选重排任何原论文已有 Table（若存在自建 Markdown 表格，确认原文无对应表且语法渲染正常）。
- [ ] 所有嵌入的原论文图/表截图均已逐张打开查看复核：仅包含单个目标图/表本体及 caption，无整页 PDF 截图、无无关正文残留、无边缘截断且清晰可读。
